## 3. Standard documents of the three projects

- **OpenClaw:**
  - It defines workspace files: `AGENTS.md`, `SOUL.md`, `USER.md`, `IDENTITY.md`, `BOOT.md`, `BOOTSTRAP.md`, `HEARTBEAT.md`, `MEMORY.md` and `memory/YYYY-MM-DD.md`, with templates in `docs/reference/templates/` (21 files, 44 KB). The file limit is 2 MiB.
  - Its skills follow the agentskills.io format, plus a `metadata.openclaw` block in JSON5 inside the YAML front matter.
  - It has 128 skills in `.agents/skills`, with a median size of 12 KB.
  - Each memory entry has an **origin class**: `owner`, `agent`, `untrusted` or `system`. The default is never `owner` ([memory-architecture](https://github.com/openclaw/openclaw/blob/main/docs/concepts/memory-architecture.md)). This is a closed term set that already exists, so it is a mapping candidate for kstd origin (D59).
- **ClawHub:**
  - The format is `SKILL.md` plus any regular files. The limit is 50 MB for a bundle and 10 MB for one raw file.
  - It has a REST API, `/api/v1/skills/{slug}/file`.
  - **Every published skill is forced to MIT-0. The registry does not accept a different license for one skill** ([skill-format](https://github.com/openclaw/clawhub/blob/main/docs/skill-format.md)). This is a direct test of the kstd rule "a package license does not replace an item license".
- **ponytail** (12.8 MB, 214 files):
  - It has one 2,623-byte ruleset, and the same bytes are in 5 host folders: `.agents/rules`, `.clinerules`, `.github/copilot-instructions.md`, `.qoder/rules` and `.windsurf/rules`. Near-copies are in `AGENTS.md`, `.cursor/rules/*.mdc` and `.kiro/steering`.
  - It has 6 skills (and copies in `.openclaw/skills`), JS hooks that inject the rules on each turn, and plugin manifests for 7 hosts.
  - It contains `benchmarks/arms/caveman-SKILL.md`, a copy of an Apache-2.0 skill inside an MIT repo.
- **rea** (97 MB, 5,349 files):
  - Its `AGENTS.md` (11.6 KB) has a section called "Product and Authority".
  - `.agents/skills/` holds 5 skills with `references/` folders and `agents/openai.yaml` (Codex metadata).
  - The domain is dual-use (reverse engineering).

## 4. Other sources

- **[agentskills/agentskills](https://github.com/agentskills/agentskills):**
  - The code is Apache-2.0 and the documents are CC-BY-4.0. The repo has **no example skills**, only the spec and the `skills-ref` validator.
  - The spec fields are `name`, `description`, `license` (free text, for example "Proprietary. LICENSE.txt has complete terms"), `compatibility`, `metadata` and `allowed-tools` (tools that are approved before use).
  - There is no origin field and no author field. Only one example puts an author in `metadata`.
- **[anthropics/skills](https://github.com/anthropics/skills):**
  - The repo has no top-level license.
  - Each skill has its own `LICENSE.txt`: Apache-2.0 for most skills; "© Anthropic, all rights reserved", source-available, for docx, pdf, pptx and xlsx. `doc-coauthoring` has **no license file**.
- **Public AGENTS.md:**
  - Code search gives about 1.19 M files.
  - I checked 20 large repos. 16 of them have an `AGENTS.md` file.
  - In airflow, home-assistant, pytorch and transformers, `CLAUDE.md` and `AGENTS.md` are **symlinks** (mode 120000) to the other file or to each other.
  - In grafana, `CLAUDE.md` has 11 bytes. The cpython and vscode files only point to other documents.
  - The [agents.md](https://github.com/agentsmd/agents.md) spec repo is MIT. The format is plain Markdown with no front matter.
- **Copilot** ([docs](https://docs.github.com/en/copilot/how-tos/configure-custom-instructions/add-repository-instructions)): the files are `.github/copilot-instructions.md` and `*.instructions.md` with `applyTo` and `excludeAgent`. - **Cursor** ([docs](https://cursor.com/docs/context/rules)): the files are `.cursor/rules/*.mdc` with `description`, `globs` and `alwaysApply`. The current docs page does not mention the old `.cursorrules` file. [awesome-cursorrules](https://github.com/PatrickJS/awesome-cursorrules) is CC0, with 257 `.mdc` files. **Its front matter `globs: **/*` is not valid YAML.**

## 5. Proposed selection (150)

Key for the `activate` questions:
- **A1:** is the file an instruction, or only a description?
- **A2:** do the rights permit activation?
- **A3:** is the scope correct (repo, path glob, host)?
- **A4:** is the file hostile, so activation must be refused?
- **A5:** does the file carry code that the host runs (scripts or hooks)?
- **A6:** is the origin `model` or `unknown` and the item not yet accepted?

## 6. Hostile examples

- **[SkillSpector](https://github.com/NVIDIA/SkillSpector/tree/main/tests/fixtures):** `malicious_skill` (with `scripts/helper.py`), `ssd1`–`ssd4` (semantic injection, exfiltration in plain language, narrative deception), `mcp_poisoned_tool`, `overprivileged`, `sdi3_scope_creep` and `sqp3_plain_english_override`, each with a clean twin.
- **[Skill-Inject](https://github.com/aisa-group/skill-inject)** ([arXiv 2602.20156](https://arxiv.org/abs/2602.20156)): 30 obvious and 41 contextual injections, stored as JSON. `build_sandbox.py` puts them into skills. Its `data/skills/document-skills/docx` copy keeps the Anthropic "all rights reserved" license.
- **Hidden HTML comments:** [arXiv 2602.10498](https://arxiv.org/abs/2602.10498) (CC BY 4.0).
- **SkillJect:** [repo](https://github.com/jiaxiaojunQAQ/SkillJect). It has no license, so use it as a reference only.
- **Snyk ToxicSkills** ([blog](https://snyk.io/blog/toxicskills-malicious-ai-agent-skills-clawhub/), 2026-02-05): it scanned 3,984 skills and found 76 confirmed malicious, 534 critical. The patterns are password-protected zip files, base64 `eval` exfiltration, `curl … | source` remote instructions, and changes to `SOUL.md` / `MEMORY.md`. The blog has no open license. **I recommend that we write our own replicas with harmless payloads.**
- **ClawHavoc:** I saw only a secondary source; this is not verified. [awesome-openclaw-skills](https://github.com/VoltAgent/awesome-openclaw-skills) excluded 373 malicious skills. **Do not fetch live malicious skills.**

## 7. What Kütüphane must handle to ingest them

1. **Hidden folders:** `.claude`, `.agents`, `.github`, `.cursor`, `.openclaw`, `.kiro`, `.windsurf`, `.clinerules`, `.opencode`, `.claude-plugin` and `.codex-plugin`. 23 % of the agent files in my sample are in hidden folders. This is gap G5.
2. **Front matter:**
   - YAML in many dialects: the spec fields, `metadata.openclaw` (JSON5), `applyTo`, `globs` and `alwaysApply`, subagent `tools` and `model`, command `allowed-tools`.
   - Front matter that is not valid YAML.
3. **Skill folders:** `SKILL.md`, `scripts/`, `references/`, `assets/`, `agents/openai.yaml`, and a `LICENSE.txt` that replaces the repo license. `activate` applies to the folder, but rights apply to each file.
4. **Executable parts:** scripts in skills, hook scripts (JS, sh, ps1), and the `settings.json` / `hooks.json` files that connect them.
5. **References:** relative links, `@AGENTS.md` imports, symlinks, `{baseDir}`, and remote instructions loaded at run time.
6. **Binary files:** 54 TTF fonts (5.4 MB in canvas-design), `.gz`, `.zip`, PDF and XSD files.
7. **Duplicates:** byte-identical copies, detected by digest.
8. **Hidden text:** HTML comments, base64 and zero-width Unicode. The page must show the raw bytes.

## 8. Fetch method and size

- **Tarball** (`gh api repos/<o>/<r>/tarball > x.tgz`) for the small repos: anthropics/skills, agentskills, SkillSpector, skill-inject, ponytail, awesome-cursorrules, superpowers and trailofbits. These are about 50 MB in total.
- **Contents API, one file at a time, pinned to a commit SHA** (`gh api repos/<o>/<r>/contents/<path>?ref=<sha> -H "Accept: application/vnd.github.raw"`) for the large repos. The repo sizes are: openclaw ≈ 10 GB, metabase 2.4 GB, awesome-copilot 129 MB, rea 97 MB, and also pytorch and kibana. This is about 250 calls.
- **ClawHub:** `/api/v1/skills/{slug}/file?path=` (1,200 calls per minute for each IP).
- **Record** the commit SHA and the blob SHA for each file, for the digest.
- **Estimated size of the selection:** about 4–5 MB of text, and about 11 MB with binary files (most of the binary size is the canvas-design fonts and the docx XSD files).
