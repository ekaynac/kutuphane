# Origin values for content that a program makes without generative AI

## 1. Answer

The operator's premise is only partly correct. Several groups have studied this kind of content, but no group has an origin value for text or data that separates a program transform from a machine recording, with defined behaviors for each.

- **W3C AI Content Disclosure CG.** Issue [#9](https://github.com/w3c-cg/ai-content-disclosure/issues/9) asked about "deterministic programmatic content" (sensor readings, database queries, template-rendered data). P.-A. Champin raised it at the Web & AI IG on 2026-03-09. The group closed it on 2026-09-21 and added no new value. The [final report](https://w3c-cg.github.io/ai-content-disclosure/) (Final, 2026-10-09) puts such content outside its scope. It says to disclose it as `human-only` if no generative AI was used. Its no-AI list includes template-based mail merge, sensor readings, deterministic rule engines and "server-generated tables". The report also says: "a generative AI system can also operate deterministically", and "Repeatable output alone does not exclude a generative AI system".
- **IPTC** has had non-AI terms since 2022. C2PA uses them.
- **DPV** has `ObservedData` and `DerivedData`.
- **PROV** has `SoftwareAgent`, but it does not separate a model from a plain program.

**Recommendation: add TWO values, `programmatic` and `observed`.** I do not recommend the name `generated`. In DPV, `GeneratedData` means data made "without relation to existing data i.e. it is not derived or inferred from other data". That is the opposite of a typedoc page. Many readers also take "generated" to mean "AI-generated". The name `programmatic` comes from the Disclosure CG report ("programmatic, out of scope"). The name `observed` comes from DPV and OpenTelemetry.

## 3. Values

| Value | Definition | Required fields |
|---|---|---|
| `programmatic` | A program made the content from recorded inputs by fixed rules. No AI technique was used: no trained model and no logic- or knowledge-based inference engine. Every input is `human`, `observed` or `programmatic`. | `inputs` (including the template and config); `software_agent: {name, version, digest?}` |
| `observed` | A device or program recorded events or states of the world (logs, captures, sensor or monitoring data) and changed nothing in the content. | `observed_at` (event time); `software_agent` (the recording system) |

**Precedence:** if any input of a program is `model` or `unknown`, the output is `model`. If an input is `assisted`, the output is `assisted` and keeps that input's `reviewed_by`. This follows the CG: text that a template places stays the text of its author.

**Content edits:** a deterministic edit that keeps the main content (a formatter, a dictionary spell-check) keeps the input's origin. This is IPTC `algorithmicallyEnhanced` used as an action, not as a source type.

**Mapping:**

| kstd | IPTC / schema.org | C2PA `c2pa.created` | Disclosure CG | PROV | DPV | SPDX |
|---|---|---|---|---|---|---|
| `programmatic` | `dataDrivenMedia`; `algorithmicMedia` if the only inputs are parameters | `digitalSourceType` as in the IPTC column; `softwareAgent`; inputs as `inputTo` ingredients; no `ai-disclosure` | `human-only` | Activity `used` inputs, `wasAssociatedWith` SoftwareAgent, `hadPlan` template | `DerivedData` (not `InferredData`, not `GeneratedData`) | `createdUsing` Tool; `hasInput` |
| `observed` | `digitalCapture`; `screenCapture` for screens; no IPTC term for logs [INFERENCE: `digitalCapture` is the closest] | `digitalCapture` / `screenCapture`; `softwareAgent` = the device or logger | `human-only` | Activity `wasAssociatedWith` SoftwareAgent; `generatedAtTime` | `ObservedData` / `ObservedPersonalData` | `createdUsing` Tool |

The CG word `human-only` is a poor fit for these items, but the report gives it that meaning ("no generative AI involvement"). kstd keeps its own value internally and writes `human-only` only on export.

## 4. Behaviors (D53)

| Behavior | `programmatic` | `observed` |
|---|---|---|
| AI marking on export | None, because the precedence rule already moves AI-tainted output to `model` or `assisted`. | None. |
| Authority | It gets no authority of its own and takes the acceptance and rights of its inputs. It is not independent evidence. A withdrawn input withdraws it. | A primary source: evidence with `observed_at`. It never gets a `mandate`; the system refuses one. It is not stale over time, only dated. |
| Change | An input change or a new generator version sets the item to `pending` until it is regenerated. | It cannot change. An edited recording is a new `programmatic` item. |
| Erasure | Erase the input, then regenerate the output. Never patch the output. | Delete the record or its key, or redact. A redacted copy is `programmatic` with the raw record as its input. |
| Personal data | Inherits the strictest input value. | Default `unknown`, which counts as `yes`, because logs contain IP addresses and user IDs. Retention applies. |
| Trust | Acceptance can be automatic under a signed delegation that names `software_agent` and its version (D54). A bad version suspends all outputs that it made. | Trust is per instrument. A faulty sensor or logger in a time window suspends its observations from that window. |
| Validation | Without `inputs` or `software_agent`, the item counts as `unknown`. | Without `observed_at`, the item counts as `unknown`. |

## 5. A tool that wraps a model

A template that an LLM fills in is `model`. It is `assisted` only when a named person reviews the final text (CG: "approving an automated workflow alone is not review"). The template is a scaffold and does not change the origin. The CG lists automated reporting systems that use an LLM under `ai-autonomous`.

If an LLM chooses among fixed sentences that a person wrote, the result is still `model`, because a model inference decides the content. [INFERENCE: this is stricter than the CG text scope, but it fails closed.]

An LLM with temperature 0 is `model`.
