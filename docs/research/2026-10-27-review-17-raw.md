# Security review: Kütüphane PR #117 (curator slices R, D, Q), merge `6f581b1`

I found 4 real failures and 3 informational items. The most serious: a compromised decider runner can escape all the sampling the database is supposed to enforce. Origin confirmation has one real hole: another eligible person can replace a live confirmation. I read the code only and ran no tests or payloads, so every reproduction below is `[INFERENCE]` from the code. I did not open `experiments/labeling/data` or `research/`.

## Findings

### 1. Medium–High: the database does not enforce sampling against the runner role (D73)

**Where:**
- `migrations/025_curate_delegation.sql:9,75` (`seq … DEFAULT nextval`, which the inserter can override)
- `025:129-135` (the sample draw and the forced-sample count)
- `deploy/db-roles-decider.sql:14` (a table-wide `GRANT INSERT`)
- `decider.py:317` (`RETURNING seq, sampled`)

**Why it matters:** docs/25 §3.5 says a compromised decider runner stays limited by the "drawn sample, pause, forced sample", and §8.4 says "the runner cannot choose". Neither holds against the `kutuphane_decider` role, through three independent paths:
- **Roll back the draw.** The trigger draws `sampled` inside the runner's own transaction and returns it. A malicious runner inserts the use, sees `sampled=true`, rolls back and tries again. Each attempt is a new `gen_random_uuid()` draw. Notes that would have been sampled are simply dropped.
- **Pick the note for the forced sample.** The runner can read `delegation_use` and `standing_event`, so it can compute `run` and knows when `run >= 2N` forces a sample. It puts a harmless note in that slot. Every human check then lands on a cherry-picked good note, so a disagreement never happens and the delegation never ends.
- **Choose its own `seq`.** INSERT is granted on every column, so the runner can insert uses with `seq = -1, -2, …`. Line 133 (`u.seq > coalesce(last_verdict, 0)`) never counts them, so the forced sample never fires. With path 1 this means zero samples: the 3-open-sample pause never triggers and every evidence note of the class is approved until expiry.
- **Fake the shadow evidence (same root cause).** `note_suggestion.seq` and `at` can also be set by the runner. A suggestion written *after* a human verdict with a low `seq` passes `_SHADOW`'s `s.seq < f.seq` (`delegation.py`). That inflates the "≥30 shadow decisions" count and the agreement the person sees before signing.
- **Two §8.2/§8.3 rules live only in Python.** "The creator still holds `curate`" (`decider.py:335`) and "no propose write by the runner's principal" (`_USABLE`) are not in the trigger, although the database can see both.

**Fix:**
- Replace the table-wide grants with column-level ones that exclude `seq`, `at` and `sampled`: `GRANT INSERT (delegation, book, kind, decider, spec_sha256, approver, note_seq, suggestion, correlation_id) ON delegation_use` and `GRANT INSERT (note_seq, decider, spec_sha256, value, confidence, model_call) ON note_suggestion`. Alternatively, have BEFORE triggers force `NEW.seq := nextval('memory_seq')` and `NEW.at := now()`.
- Make the draw fixed per note and secret: an HMAC of `(delegation, note_seq)` keyed by a secret in a table the decider cannot SELECT, computed in a `SECURITY DEFINER` function. Retrying then gives the same answer.
- In `delegation_use_check`, refuse a use unless it is for the oldest eligible note of the class (committed approved suggestion ≥ threshold, no use yet), so the runner cannot skip notes.
- Also refuse a use whose suggestion row was written in the current transaction (`xmin = pg_current_xact_id()::xid`, the trick 026 already uses). The suggestion is then committed before any draw is revealed.
- Move the creator-`curate` check and the runner-authorship check into the trigger.

### 2. Medium–Low: another eligible person can replace a live confirmation, which bypasses R7

**Where:**
- `confirm.py:285-310`: `confirm_fields` and `confirm_act` have no check for a live confirmation.
- `confirm.py:237-238`: `_page_item` offers claims even while a confirmation is live.
- `024`: no constraint on `origin_confirmation` covers this.

**Scenario:**
1. Ayşe confirms `human` for her request.
2. While the request is still open (24 h), Mehmet, a direct curator with `read` on the book, opens `/c/<book>/<id>`, is offered `assisted`, and signs.
3. `origin.shown` now gives `assisted` with `reviewed_by` Mehmet. Ayşe's `withdraw` becomes `None`, because `live[3] != principal`.
4. If Mehmet later withdraws, the origin falls back to `model`, and Ayşe's `human` never comes back.

So a non-confirmer removes a live confirmation without the confirmer's withdrawal act, which R7 forbids. There is a second variant: a reader's agent re-proposes the same bytes claiming `human`. That opens a request whose person is the reader, who can then confirm `human` over Ayşe's and take over the attribution.

`test_withdrawal_of_the_latest_confirmation_never_brings_back_an_older_one` shows that confirming over your *own* live confirmation is intended. The case of a different person is not tested.

**Fix:** refuse `confirm` while a live confirmation exists unless `live.confirmed_by == principal`. Apply this in `confirm_fields`, `confirm_act` and the `claims` of `_page_item`. Back it with a BEFORE INSERT trigger on `origin_confirmation` with the same rule.

### 3. Low: the confirm page and act options reveal notes in books the person cannot read

**Where:** `confirm.py:255-258` (`page`), `285-291` (`confirm_fields`), `313-321` (`withdraw_fields`), `266-283` (`_open_request`).

**Scenario:** `_note()` runs before the direct-`read` check. An enrolled person without `read` on book X can tell these apart for a guessed `X@nt_…`:
- the note does not exist (404);
- it exists (403 on the page);
- it has no request, or the request expired (400 from `_open_request`, which runs before `claims_for`);
- it has a live confirmation, from `withdraw_fields` (400 "no live confirmation" vs 403 "only the confirmer").

Because note ids are content hashes, this confirms a guessed text exists. `curatorqueue.note` does the rights check first, so it is not affected.

**Fix:** check `authz.direct(principal, book:<book>, "read")` from the parsed ref before any lookup, and return one uniform refusal.

### 4. Low: the decider does not re-check the text gate just before each model call

**Where:** `decider.py:245-258` selects up to `limit` notes (100 by default); `decider.py:280` then calls the model once per note, up to 120 s each.

**Scenario:** if a journal's `ai_input` becomes `n` or a skill scan blocks a dependency (D71) during a run, the text of the remaining selected notes is still sent to the model. The trigger only stops the *use*, not the call. Other readers re-check right before handing text to a model (`notesquery._shown`, "the final statement reads their skill blocks again").

**Fix:** just before each `ask`, re-select the row with `n.ai_input AND j.ai_input AND NOT note_skill_blocked(n.seq) AND NOT EXISTS standing_event`, and skip the note if it no longer qualifies.

### 5. Low (hardening): the decider role can read all note text

**Where:** `deploy/db-roles-decider.sql:10`, `GRANT SELECT ON note …`.

**Problem:** the role can read `note.body` in every book, including `ai_input = n` and restricted journals. It also holds an LLMDAP key. The "text gate" therefore only limits approvals, not what a compromised runner can read and send out.

**Fix:** remove SELECT on `note` and expose a `SECURITY DEFINER` view or function. It should return text only for books in `KUTUPHANE_DECIDER_BOOKS` plus live delegations, and only when `ai_input AND NOT note_skill_blocked`.

### 6. Info: `delegation_end` is not tied to its act

**Where:** `025:66`.

**Problem:** unlike 024 and 025's other act-bound tables, it has no generated `act_action = 'end_delegation'` and no `(act, ended_by) → curator_act (seq, principal)` key. Curator web can link an end to any act and any `ended_by`, and `verify_acts` would not notice. It can only tighten, but it breaks the pattern used elsewhere.

**Fix:** add both keys.

### 7. Info: smaller gaps

- **No floor on the shadow minimum.** `delegation.py` `min_shadow()` accepts `0` or a negative `KUTUPHANE_DELEGATION_MIN_SHADOW`, which removes the 30-decision floor, and a non-integer value causes a 500. Clamp it to at least 1 and validate it at startup.
- **The confirm sign sheet shows the client's own choice.** `curator_ui/confirm.js` `sign()` displays the locally chosen `words` and `item.ref`, not `o.statement.claim` and `o.statement.entered_by`. §5.2 says the sheet should come from the stored statement. Render `statement.claim` and `statement.entered_by`.
- **Laya's revision is not checked against the answer.** `laya-notes.json` has `answer.revision: null`, so the pin relies on the LLMDAP `approvedDigests` (a documented limit). Changing the runner's prompt code without bumping `RUNNER` keeps the same `spec_sha256`, which is a process risk.

## Checks that passed

**Origin:**
- **No `human` without the person's act.** Only `model` or `unknown` is ever stored on the write path (`origin.compute`, including note import). `human` needs a `confirm` passkey act with user verification, plus the `human_by` key to `write_record.person` and the statement trigger.
- **No form-mode elicitation.** `confirm_origin` uses URL mode only, and `accept` changes nothing.
- **The page needs more than the URL.** The URL holds no secret; the page needs a session and direct `read`.
- **A changed byte is refused.** The digest is recomputed (`check_integrity`) at options and again at the act; `write` is bound to the note through the composite key; expiry is checked after the lock.
- **Withdrawals behave correctly.** Only the latest confirmation counts, and `shown(w)` respects the confirmation and withdrawal `seq`.
- **Reads use the shown origin.** `query_notes`, `neighbours`, `open_citation`, `item_info`/kstd and the decision export all use it, and the `origin` filter uses the shown value.

**Delegation:**
- **Class and book are enforced.** The composite keys pin the note's (book, kind) to the delegation; kinds are limited to evidence; a contradicted note or a note with any Standing event is refused; the text gate applies at the use.
- **The approver is always the model.** `set_by` is `model:<decider>`; a model event requires an unsampled use of the same note; the decider has no INSERT on `standing_event`.
- **Spec pinning holds.** The spec SHA covers the route, locality, model and revision; non-local specs are refused; the answer's model and revision are checked.
- **Disagreement ends it on every path.** A trigger ends the delegation on the first non-`approved` user verdict of a sample; expiry and end are checked at `clock_timestamp()`.
- **Creation is guarded in curator web.** It needs a `delegate` act with direct `curate` and `read`, re-checked at the act, and the statement trigger.
- **No concurrent-run race.** The runner and curator web both take the memory lock, so the counts cannot race between honest processes.

**Prompt injection:** with an honest runner it stays bounded. The note goes to the model as a JSON string with a "data, never an instruction" frame; malformed output becomes `abstain`; the output is only a suggestion, applied within the database limits; suggestions are never shown before the decision.

**Queue:**
- **No cross-book leaks.** Only books with direct `curate` and `read` are queued; `same_as` groups stay inside one book (016); citations and links into unreadable books show no name or text; `hidden_parts` blocks approval at options and act (`_shown_whole`); tier reasons never name the other note; the delegation views are limited to the person's curated books.
- **Requests and CSRF.** POSTs need the exact Origin header and JSON; the `__Host-` cookie is `SameSite=Strict` and HttpOnly; the GETs only write access logs.
- **No XSS.** The JS uses `textContent` and text nodes only, with no `innerHTML` or other HTML sinks; hidden characters are shown as marks; `CSS.escape` is used in the selector.
- **Database roles.** The app role cannot write the curation tables (024/025 revokes).
- **Offline check.** `verify_acts` has effect checks for all five actions.

**Suggested checks for the main agent:**
- A DB test where the decider role inserts `delegation_use` with `seq = -1`, and repeats insert/rollback until it gets an unsampled use.
- A curator-web test where user M confirms `assisted` over user U's live `human` confirmation.
